## 握手修复细节与部署条件

票据解析严格限制账号/版本 UTF-8 长度、编码、固定字段与 64 字节签名边界，明确使用 P-256 / IEEE P1363。先验签再分类版本错误。未知发送者、非房主 challenge、冒用 playerId、未请求/已完成的 response 均不能改变他人验证结果。Warn 模式失败后允许开局，Kick 模式阻止并延迟踢出；待验证阶段均阻止开局。恢复按钮时先让原版 Update 重算人数条件，避免直接放行。

服务器使用实际加载私钥导出公钥，并对并发签名加锁。没有部署或访问线上验证服务器，也没有更换客户端内置公钥。要恢复线上验证，必须：

1. 确认实际服务器 `/pubkey` 与 `LightAPI/Handshake/HandshakeCrypto.cs` 的 `PublicKeyPem` 一致。若替换公钥，应重新构建两 DLL，再重新生成 hash；不要使用替换公钥前的白名单。
2. 本次 Release `LightPlugin.Version` 为 `0.0.1`；hash 为 SHA-256 前 4 字节转小端有符号 int32：API `966736142`，主插件 `-332511401`。`Output/official.generated.json` 只是独立示例，未覆盖真实服务器配置。
3. 将该版本条目合并到服务器 `data/official.json`。房主 `EnableHandshake=true`，所有客户端配置与内置公钥对应的签票服务 URL；普通客户端 `EnableHandshake=false` 也会响应房主挑战。
4. 测试合法构建成功、未登记构建拒签后超时、公钥错误验签失败、服务器断开超时，以及 Warn/Kick 两模式。

协议边界：服务器接收的是客户端声明的 hash、账号及 nonce，无法证明远端真正加载的 DLL。签名可防伪造票据，不提供强远程完整性证明；账号不可用时身份绑定也不完整。说明文档已修正原有反篡改保证的夸大表述。

## 验证与重放

主插件/API 继续使用已有 net6.0、AU 19.0 x64 与 BepInEx 6 依赖。构建使用 .NET SDK 10.0.401，支持现有 C#14 语法；验证服务器与独立回归项目为 net10.0。未改变插件运行框架。

在仓库根目录运行（需要 .NET 10 SDK 和 Python 3）：

```bash
DOTNET=dotnet bash Tools/run-regressions.sh
python3 Tools/release-manifest.py
```

脚本顺序构建 Debug→Release（两配置共用 Output，最后留下 Release），构建服务器，提取实际配置/弹框函数，再运行回归。测试链接真实 HUD/握手源码，并提取实际配置/弹框业务函数；外部 Unity/IL2CPP/Hazel 等由最小模型替代。HTTP 测试启动真实服务器并生成独立测试密钥，不使用用户私钥。最后使用 Mono.Cecil 检查成品 DLL 的 Harmony 属性与 HUD 目标/优先级。

结果：69 项检查通过；主插件最终 Debug/Release 构建各 0 error、51 warning，主要为已有空值和未用字段等；服务器 0 warning、0 error。完整日志在交付包 `validation.log`，工作区 `/www/LID/final-validation.log`。旧配置/旧弹框各有一个明确的预期失败断言，证明回归可区分本次根因。

## 实机验收步骤

关闭游戏，将 `Output/Light.dll` 和 `Output/LightInDark.dll` 一起替换测试环境 `BepInEx/plugins` 对应文件。本轮没有 Windows 游戏目录，未执行实机部署。保留原 DLL 便于回退；避免同时加载旧 `Light.Nova.dll` 等重复插件。

1. 新开大厅，确认开始/准备按钮位置；开始倒计时后点击取消、跳过，确认位置、缩放、文字及两半点击区正确。
2. 依次打开 MOD、船员、内鬼、中立及其他职业页签，进入一个职业详情，将数量在 0 和最大值间反复切换、返回列表；确认只出现该职业配置，滚动不溢出。
3. 原版游戏设置↔职业↔MOD 来回切换至少十轮，关闭再打开菜单；确认没有原版分类头、地图预览或配置行外泄，原版页仍可正常编辑。
4. 至少打完一局回大厅，悬停复盘按钮，检查左上提示及屏幕四角的配置提示；Tab 固定/移开/取消/关闭菜单，离开再进大厅，确认弹框和复盘按钮无残留。
5. 在大厅衣柜和游戏任务等交互点反复靠近/离开；确认 Use/Pet 不飞向中心，会议、死亡、开图/小游戏及小 HUD 下位置正常。
6. 两客户端测试合法握手、加入时 LocalPlayer 延迟就绪、丢首包/网络延迟、服务器不可达、版本/hash 不匹配、房主切换和离房重进。特别核对人数不足时验证结束不会放行开始按钮、跨房不会误踢。
7. 分别保存光标 0/1/2 后重启，确认保留选择；检查 `LightLog.log` 和 `Player.log` 新增异常。
